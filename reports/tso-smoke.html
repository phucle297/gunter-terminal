Reviewer Findings (from v0.1.0-review.html)

Corrected Assessment: Reviewer False Positive

Reviewer reported: "Parser recreated on each loop iteration" (main.rs:34)
Actual code: vte::Parser::new() is at line 26, OUTSIDE the loop. Parser state IS preserved across reads.
Verdict: False positive. The reviewer confused GridPerformer (thin borrow, no vte state) with vte::Parser (stateful).

Real Issue Identified

performer state reset across reads — GridPerformer is constructed fresh each read() iteration (main.rs:34). The performer holds fg, bg, flags state. If an SGR escape sequence is split across two read() calls, the color state resets between them, causing the character to appear in default colors.

Impact: Phase 1 — negligible (single-read for short commands). Phase 2 — real issue under load.
Fix for v0.2: Persist performer state across reads (move fg/bg/flags into a separate struct owned outside the loop, or make GridPerformer own the grid rather than borrow it).
